## Purpose
Визначити GDPR рамку для обробки персональних даних у Dzvin.co + DIP, включно з R&D активностями.

## Roles
- Controller: to be specified per deployment/legal entity.
- Processor/Sub-processor: to be specified with DPA annexes.
- Joint controllership scenarios: to be assessed for partner studies.

## Data Categories
- Account and identity metadata.
- Wellbeing self-report data.
- Psychometric and behavioral signals.
- Organizational role/access metadata.
- Decision/audit artifacts.

## Lawful Basis Framework
- Contract performance for core service operations.
- Legitimate interest where applicable with balancing test.
- Explicit consent for optional sensitive processing/research paths where required.

## Data Subject Rights
- Access
- Rectification
- Erasure
- Restriction
- Portability
- Objection

## Operational Rights Handling
- Verified request workflow.
- SLA by request type.
- Logging of request lifecycle.
- Appeal/escalation path.

## Data Minimization and Purpose Limitation
- Collect only necessary data for defined use-cases.
- Separate operational vs research processing purposes.
- Restrict secondary use without proper basis.

## Retention and Deletion
- Retention matrix by data class.
- Automated deletion/anonymization schedules.
- Legal hold exceptions and governance.

## International Transfers
- Transfer mechanism inventory.
- SCCs or equivalent safeguards where needed.
- Third-country risk assessment process.

## DPIA and High-Risk Processing
- DPIA triggers for sensitive-scale analytics.
- Periodic DPIA review for model/policy changes.
- Residual risk acceptance workflow.

## Breach Response
- Detection and triage playbook.
- 72-hour notification readiness.
- Impacted subject communication policy.

## Acceptance Criteria
- Є актуальний Record of Processing Activities.
- Права суб'єктів даних обробляються за затвердженим SOP.
- DPIA покриває high-risk processing сценарії.
