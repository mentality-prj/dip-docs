# 13 — Grant / R&D Risk Register

Status: active reusable grant module

| ID | Risk | Impact | Control / response |
|---|---|---|---|
| R1 | Test A/B/C decision-quality non-inferiority fails | High | Treat as falsification; do not rescue by post-hoc tuning; narrow thesis if evidence requires |
| R2 | 50% engineering-effort threshold fails | High | Preserve measured result; identify reusable-cost break-even separately; do not change accounting after results |
| R3 | Blind Test C contamination | High | pre-reveal freeze, independent selection/reveal record, immutable manifests |
| R4 | Specialized baseline is not comparable | High | equal scope/information/compute rules and baseline review before freeze |
| R5 | Reference or data provenance unavailable | High | reference hierarchy, snapshot checksums, invalidity taxonomy, no outcome-based exclusions |
| R6 | Domain logic leaks into Core/plugin hidden optimizer | High | semantic-extension audit; hard generalization-failure rule |
| R7 | External validation unavailable | Medium | internal evidence remains valid; pursue non-consortium LOI/pilot; do not claim external validation |
| R8 | Call requires co-financing/consortium after rule publication | High | stop application immediately under financing gate |
| R9 | Grant-specific scope distorts QDIP product | High | thin overlay architecture; Core thesis cannot change to fit a call |
| R10 | Open-source requirement conflicts with IP strategy | High | isolate grant-specific adapter/app; legal/licence review before submission; NO-GO if required disclosure is unacceptable |
| R11 | Cloud/model/data costs or APIs change | Medium | versioned runtime/environment binding; budget contingency only if eligible |
| R12 | Security/dual-use/data restrictions block deployment | High | call-specific compliance review; minimize sensitive data; human authority and audit controls where applicable |
| R13 | Customer willingness-to-pay unproven | High | pilot/LOI/customer-discovery evidence; economic-value metrics before scale-up |
| R14 | Grant payment timing creates cash-flow gap | Medium/High | record pre-financing schedule and reject execution plan that requires unavailable working capital |

## Rule

Risks are not marketing text. Each application must select the relevant risks, assign an owner, trigger and mitigation, and keep unsuccessful research outcomes visible.
