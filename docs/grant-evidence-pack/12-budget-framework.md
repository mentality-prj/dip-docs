# 12 — Budget Framework

Status: active reusable grant module

## Financing gate

QDIP application work proceeds only when the call permits a financing structure compatible with the project rule:

- single applicant permitted;
- no mandatory consortium;
- no mandatory applicant cash co-financing;
- grant/FSTP/prize/non-repayable funding compatible with the planned work.

A call that requires own contribution is rejected unless this rule is explicitly changed before application work starts.

## Budget construction

Build every budget from work packages and measurable deliverables, not from an arbitrary request equal to the programme maximum.

Canonical cost buckets:

1. personnel / founder technical work;
2. compute, model/API and hosting costs where eligible;
3. data acquisition/licensing where eligible;
4. test/validation infrastructure;
5. external specialist services only where eligible;
6. travel/demonstration only where directly required;
7. indirect costs according to the call's formula.

## Cost-evidence rule

For each line record:

- WP/deliverable;
- quantity/time basis;
- unit-cost basis;
- eligibility source;
- amount requested;
- whether pre-financing is available;
- cash-flow timing;
- evidence/quote where required.

## Small-grant scope guidance

- ~EUR 20k: one bounded technical/evidence milestone, not A+B+C.
- ~EUR 40k: Test A plus a second bounded validation/productization milestone if eligible.
- ~EUR 50k–60k: one call-specific demonstration/pilot plus reusable evidence/product hardening.

Exact allocations belong in the program overlay because subcontracting, equipment, indirect cost, travel and payment rules differ by call.

## Cash-flow gate

A nominally 100%-funded grant can still be unsuitable if payment is heavily back-loaded and the project cannot finance execution until reimbursement. Every overlay must therefore record payment timing separately from funding rate.
