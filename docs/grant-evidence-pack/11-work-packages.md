# 11 — Reusable Work Packages

Status: active reusable grant module

These work packages are modular. A small grant should fund a bounded subset; no application should pretend that EUR 20k–60k funds the entire Universal Runtime research programme.

## WP1 — Freeze and Evidence Infrastructure

Objective: make the scientific/product claim reproducible and auditable.

Deliverables:
- frozen Core/IR/API manifest;
- benchmark/version identities;
- evidence and engineering-effort ledgers;
- reproducible execution/audit tooling.

## WP2 — Test A: Readiness Recovery

Objective: execute the preregistered first-domain benchmark.

Deliverables:
- qualified implementation;
- primary result manifest;
- specialized-baseline comparison;
- engineering-effort evidence;
- terminal interpretation.

## WP3 — Test B: Procurement

Objective: test repeatability in a materially different decision family.

Deliverables:
- frozen procurement protocol;
- specialized comparator;
- primary result and effort ledgers;
- cross-domain comparison with Test A.

## WP4 — Blind Test C

Objective: falsify or support the frozen-runtime generalization claim.

Deliverables:
- pre-reveal freeze manifest;
- domain-selection proof;
- blind-domain implementation audit;
- primary result and engineering ledgers;
- consolidated A/B/C evidence.

## WP5 — Productization and External Validation

Objective: turn validated runtime semantics into a deployable product surface.

Deliverables may include:
- API/SDK hardening;
- deployment and observability package;
- security/data-governance controls;
- bounded external pilot;
- measured operational/economic outcome.

## WP6 — Exploitation, IP and Grant Reporting

Objective: convert evidence into a repeatable business and funding asset.

Deliverables:
- IP/FTO update;
- business-model validation;
- customer/pilot pipeline;
- dissemination/reporting required by the call;
- next-financing plan.

## Scope rule

Each program overlay must select only work packages that are both eligible and executable within its duration/budget. Grant-specific domain adapters are separate deliverables and must not redefine the canonical thesis.
